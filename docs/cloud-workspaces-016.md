# Cloud workspaces and record sync (0.1.6)

Cloud clients keep a durable local cache/outbox even online: losing a connection between typing and a server acknowledgement must never lose an edit. Online saves use authenticated, record-scoped D1 transactions, not database credentials in the frontend. Local workspace servers retain protocol 2.

Cloud adds a negotiated node transport to protocol 2. Only edited records and their collection metadata are read for writes; paginated node changes replace full-workspace responses. Existing clients keep the full protocol. Receipts, field comparisons, tombstones and conflict preservation remain authoritative. Changed-node history is transactional; scheduled complete backups remain available. No assumption that every workload fits Workers Free's 10 ms CPU allowance is made.

An additive migration removes the one-owner/one-workspace constraint while preserving all IDs and child rows. Existing workspace billing remains the account's billing anchor; additional workspaces inherit its plan. Storage reservations and records/files count across the owner's workspaces in atomic SQL guards. Only a paid owner can create additional workspaces or invitations. Invite recipients can use a Free account. Owners administer membership; editors change content; viewers only read/export. Downgraded shared/additional workspaces remain readable and exportable.

Workspace switching opens a separate cache/outbox. It never copies, merges or removes records. Invitations are expiring, hashed, single-use codes; no email delivery is implied. Revocation is checked on each authenticated request.

Production deployment/cutover is separate. Before applying the migration remotely, test a populated old schema, foreign-key integrity, permissions, quotas, retry/conflicts and rollback on a database copy. Preserve the old deployment and a D1 export/Time Travel bookmark. A schema rollback must preserve new workspace/membership data in an export rather than discard it.

## Implemented

- Cloud protocol negotiation (`transport: nodes-v1`), one acknowledged operation per request, record-scoped writes and bounded four-part downloads. Partial acknowledgements are compatible with older batch senders. Local/Rust services keep their existing behavior.
- D1 migrations 0005/0006 preserve workspace IDs, accounts, records, credentials, sessions and integration grants. A separate session-actor mapping prevents a shared-workspace token from acquiring its owner's account identity.
- Plus owners create named, empty workspaces and single-use seven-day invitations. Editable members change content; Viewable members read/export. Owners change/revoke permissions and unused invitations. Membership/account status is checked on every request. Sharing recipients may use Free accounts; the owner's Plus plan funds the shared workspace.
- Desktop and browser Accounts & Sync list/open workspaces and provide sharing controls. Browser cookies stay HttpOnly; desktop tokens stay in the OS credential store. Switching retains separate SQLite/IndexedDB caches, outboxes and conflicts. Viewer panels hide owner administration; permission loss preserves queued edits rather than dropping them.
- Owner-wide 10,000,000,000-byte quota includes live records, files and in-flight upload reservations across all owned workspaces. Atomic SQL guards enforce it under concurrent writes. Billing stays on the existing primary workspace; Stripe reconciliation mirrors its current plan to its additional workspaces. Expired sharing/additional workspaces remain viewable/exportable.
- Changed-record history is captured in the same D1 transaction. `GET /api/workspace/record-history?node=...` returns bounded history parts with the plan's retention horizon; scheduled full recovery snapshots remain. History parts are operator-readable recovery material, not a new visual history editor.
- Finance subscriptions can be edited, including name, amount, renewal date/frequency, category and notes. Existing IDs, creation time, paused state and unknown fields survive updates. Money/date validation rejects invalid values.
- The supplied transparent PNG is the canonical `assets/icon.png`. Generated assets cover web branding/favicons, Tauri PNG/ICO/ICNS, legacy macOS and iOS AppIcon catalogs. Aspect ratio and transparency are retained; the legacy iOS raster AppIcon uses an opaque dark canvas. `python3 scripts/generate-brand-icons.py` reproduces these assets using Pillow as a development tool.

## Deployment and rollback

Staging migrations were applied after the populated-schema tests and a private D1 export/Time Travel bookmark were saved. Replaying the exported database with both migrations retained all 3,090 checked rows; foreign-key and integrity checks passed. The private export lives outside the repository under `~/.local/state/base-migrations/2026-10-15-016/`; it is never included in source ZIPs. Only synthetic fixture rows/objects are removed by the runtime tests. The existing Vercel/Upstash production deployment is untouched.

Do not roll back by dropping new workspaces or memberships. For an incident, keep the upgraded schema and workspace-aware authentication, and temporarily switch clients back to full protocol 2 by omitting `transport` (both protocols remain supported). A much older backend's assumption of one workspace per owner is no longer safe: its provisioning query must select the deterministic primary workspace ID before it can be used as a rollback. Restoring a pre-migration database/Time Travel bookmark requires an isolated recovery copy and reconciliation/export of subsequent edits, rather than overwriting the active database.

Remaining acceptance gates: actual macOS build/runtime and icon checks; real Clerk browser/device sign-in and Stripe sandbox upgrade/cancellation; owner-workspace free-tier sync behavior; production parity/migration/cutover. Phase 2.5 remains in progress, and the original Phase 3 has not started. Use [the Mac quickstart](phase-2.5-mac-quickstart.md) for owner checks.

The signed Linux 0.1.6 AppImage is published on the existing updater feed. macOS requires a source build using the quickstart until a Mac artifact has been built and verified. The main Git branch is not pushed, preventing an unintended Vercel production deployment.
